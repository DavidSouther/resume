# Unsafe audit: crate `ctxswitch`

Standard applied: Google `unsafe_rust_review` skill (verbatim copy in `research/unsafe-rust-review-SKILL.md`). Target: Linux glibc on x86_64 and aarch64.

Verdict policy. REJECT means safe code can reach UB through the site, or no caller can discharge the contract with any premise from the evidence hierarchy. ACCEPT WITH NOTE means the operation is sound but the written proof has a missing, false or unclassified premise, or the site depends on a REJECT somewhere else.

Method. The audit is static. Contracts were read from glibc manuals, the psABI/AAPCS64 calling conventions, and the std 1.92 sources (`alloc/src/boxed.rs`, `core/src/pin.rs`, `std/src/thread/scoped.rs`). `./scripts-dev.sh build --all-targets --release` builds clean on x86_64 (emulated amd64 image). `./scripts-dev.sh clippy` could not run because the container toolchain (1.99.0) has no `cargo-clippy` component. No proof-of-concept programs were written or run, so every failure scenario below comes from code reading.

## Scope evidence

`grep -rnE 'unsafe|global_asm|asm!|extern "C"|UnsafeCell|\*const|\*mut|mem::zeroed|from_raw|transmute'` over `src/bench/`, `src/bin/umthreaddemo.rs`, `src/bin/uctxswap.rs` and `src/bin/switchbench.rs` finds no `unsafe`, no `asm`, no `UnsafeCell`, no raw pointer types and no `mem::zeroed`. Two kinds of hit remain. The first is `extern "C" fn` *definitions* of safe entry points (`bench/user.rs:21,48`, `umthreaddemo.rs:21,39,53`, `uctxswap.rs:26,36,48,49`). The second is `Pid::from_raw` (`bench/mod.rs:137,142`), a safe nix constructor. These files are not unsafe sites, but they are safe *clients* of the APIs audited below and are in scope for the soundness holes.

All unsafe sites are in `src/stack.rs`, `src/uctx.rs`, `src/regswitch.rs`, `src/green.rs`, `src/bin/uctxswitch.rs`, `src/bin/uctxmake.rs` and `src/bin/uctxrestore.rs`.

## Hazard findings

(a) Returns-twice. `#[inline(always)]` plus static atomics is not sufficient. Inlining is not guaranteed, and if it does not happen, `getcontext` saves the frame of `capture_raw`, which has already returned by the time `resume` runs. Even when the call is inlined, LLVM is not told that the call returns twice, so it may keep a value in a callee-saved register on one path and in a stack slot on the other, or reuse stack slots. That risk is real, not theoretical. The current binaries probably behave correctly only because almost nothing is live across the capture. This cannot be classified as accepted risk under the skill because no premise in the evidence hierarchy supports it. Rejected as R6.

(b) Moving `Context`. Moving the struct does not move the `ucontext_t`, so the x86_64 `fpregs` self-pointer still points at valid memory at the machine level. However, the `Box` is moved after the pointer is derived, which the std Box guidance forbids (R5). The `Pin` is decorative because the pointee is `Unpin`.

(c) Suspended frames, `Rc`, and auto traits. `Context`, `Fiber` and `Stack` are `!Send` and `!Sync` (through `Cell`, raw pointers and `Rc`), which is correct and confines every flow to one OS thread. Entry functions take no data, so cross-flow sharing goes only through `'static`/thread-local state with dynamic borrow tracking. A `RefCell` borrow held across a switch therefore stays a real, checked borrow. `Rc` clones held in suspended frames leak but are not UB. A panic in an entry hits the `extern "C"` boundary and aborts (Reference, panic at an ABI boundary), so no unwinding happens across hand-made frames.

(d) Assembly. Layouts and alignment are derived in rows 19 and 20 and are correct on both architectures. The caller's red zone is not a concern because the switch is a real call. The `ud2`/`brk` trap on entry return is a defined crash. Missing: x87 control word/MXCSR/FPCR, CFI, and namespaced or local symbols.

(e) `task_main`. Sound under the invariant described in row 22. The invariant should be written down where `run` dispatches.

(f) Stack arithmetic. Overflow is checked, and `top`/`base` are correct, but the row 4 comment is wrong. A single guard page catches overflow only when every frame touches each page in order. Rust inserts stack probes on x86_64 and aarch64, but foreign frames (glibc `printf` and similar) may not. `Drop` while frames are suspended: R3.

(g) `uc_link`. The `Rc` keeps the link's memory alive (correct), but nothing makes its *state* valid when the entry returns (R2).

(h) Safe-code soundness holes: see below.

## Rejections

1. **R1. `Context::swap` never consumes the target (uctx.rs:115-127).** Failure scenario: a flow saves into `a` inside a helper function, is resumed, and the helper returns. `a.ready` is still `true`. Any later `x.swap(&a)` (or a peer that swaps back to `a`) installs a state whose stack pointer and return address belong to a frame that no longer exists. That is a jump into reused stack memory from safe code. A made context resumed twice restarts `entry` on a stack that may still hold a suspended earlier instance. A second, related gap: `self` is not required to be the running flow, so a suspended context's state can be overwritten. Fix: `to.ready.set(false)` before `swapcontext` (restore it on the `-1` path), exactly as `Fiber::switch` does with `sp.replace(null)`, and reject a `self` that is currently ready (suspended).

2. **R2. `uc_link` validity is never established (uctx.rs:84-87).** Failure scenario: `Context::spawn(stack, Some(Rc::new(Context::blank())), f)`, or a link whose saved frame has since returned. When `f` returns, glibc `setcontext`s into a zeroed or stale state. On x86_64 that dereferences a null `fpregs` and jumps to `rip == 0` or into a dead frame. Fix: remove `uc_link` from the safe API (always null, so entry return ends the thread, or route through a trampoline that traps), or make `bind`/`spawn` `unsafe` with a precondition that the link is ready and live whenever `entry` returns.

3. **R3. Stacks are freed while they hold live suspended frames, or while they are running (stack.rs:113, reached from `Drop for Fiber`/`Context`, and from `bind` replacing `_stack`).** Failure scenario: an entry suspends by saving into a temporary `Fiber::current()` / `Context::blank()` that it owns, instead of into itself. The owning `Rc<Fiber>` is then dropped from another flow, and `munmap` runs under frames that were never dropped. Rust's guarantees that safe code relies on are stated as "the storage of a pinned local is not invalidated until `drop`" (std `pin` Drop guarantee, via the safe `pin!`) and "scoped threads are joined before `scope` returns" (std `thread::scope`). An abandoned frame's memory gets reused while those guarantees are still in force, so safe code can reach UB (for example, a scoped thread still reading the freed frame). The same happens when a flow ends up running on a stack whose owner is dropped (see R7). Fix: make `Fiber::new`/`Context::spawn`/`bind` `unsafe` with a precondition that no stack is freed while it holds unfinished frames, or track a `finished` flag set only by a crate-controlled exit path and have `Drop` *leak* (not unmap) a stack that was started but not finished.

4. **R4. Execution stacks without size or guard checks (uctx.rs:91; also `Fiber::new` with `Stack::heap`).** Failure scenario: `Context::spawn(Stack::heap(0), None, f)` makes makecontext and `f` write below the boxed slice. Any `Stack::heap(n)` that overflows at runtime corrupts neighboring heap objects instead of faulting. That is out-of-bounds writes from safe code. Fix: accept only `Stack::guarded` for execution (make the heap variant non-executable, or require `unsafe` to use it), and enforce a minimum usable size in `bind` as `Fiber::new` does.

5. **R5. Raw pointers derived from a `Box` are used after the Box moves (uctx.rs:36/53, stack.rs:18/79).** Failure scenario: on x86_64, `captured()` lets glibc store `fpregs = &uc.__fpregs_mem` and then moves the Box out (`Ok(ctx)`, `Rc::new`). The next `swapcontext`/`setcontext` reads through that pointer. Likewise, `Fiber::new`/`bind` derive `sp`/`ss_sp` from a heap `Box<[u8]>` and then move the `Stack`. std documents this as "not allowed" (non-normative, but the skill requires the stricter rule). The `Pin` adds nothing because the pointee is `Unpin`. Fix: store `NonNull<UnsafeCell<ucontext_t>>` from `Box::into_raw` and free it in `Drop` through `Box::from_raw`; do the same for the heap stack (or delete the heap backing per R4); and add `// Safety invariant:` comments on both fields.

6. **R6. `capture_raw` has an undischargeable contract (uctx.rs:135-158; consumers uctx.rs:169, uctxswitch.rs, uctxrestore.rs).** Failure scenario: `#[inline(always)]` is not honored (it is a hint), so `getcontext` saves `capture_raw`'s own frame and `resume` returns into a popped frame. Or, when inlined, a live value is cached in a callee-saved register on one return and in a stack slot on the other, because Rust/LLVM model the call as returning once. Fix: do not let Rust observe a returns-twice call. Move the capture-print-resume sequence into a small C (via `cc`) or `global_asm` shim that calls back into Rust only for the printing, and delete `capture_raw` from the public API.

7. **R7. `Fiber::switch` does not check that `self` is the running flow (regswitch.rs:176-195).** Failure scenario: `a` is suspended, and code running in `b` calls `a.switch(&c)`. `a.sp` is overwritten with `b`'s state, `a`'s frames are orphaned, and a later switch to `a` resumes on `b`'s stack while the `Fiber` that owns that stack can be dropped independently, which leads to R3. Fix: require `self.sp.get().is_null()` (return `Error::NotRunning` otherwise), and preferably track the running fiber in a thread-local and require `ptr::eq(self, current)`.

## Soundness holes reachable from safe code

- `Context::swap` to a context whose saving frame has since returned (R1).
- `Context::swap` to a made context twice when its first run saved elsewhere, which restarts `entry` over live frames (R1).
- `Context::spawn`/`bind` with `uc_link` to a blank or stale context, followed by `entry` returning (R2).
- Dropping a `Fiber` or `Context` (or calling `bind` again) whose stack holds unfinished suspended frames, which breaks the pin and scoped-thread drop guarantees (R3).
- Running on a stack whose owning `Fiber` was dropped, reached through the save-slot confusion in R7 (R3, R7).
- `Context::spawn(Stack::heap(0), ..)`, or any heap-stack overflow, which writes out of bounds on the heap (R4).
- Box-provenance violation on every x86_64 `Context` from `captured`/`spawn`, and on every heap-stack `Fiber` and `Context` (R5).
- Not a hole: `Fiber::new` with an entry that returns traps deterministically (`ud2`/`brk`). A panic in an entry aborts at the `extern "C"` boundary. `green` nested `run()` aborts rather than causing UB.

Open rejections: 7
